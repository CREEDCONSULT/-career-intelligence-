# Audience Positioning

One project, four readings. Every post should let at least one of these audiences see themselves.

## 1. Recruiters / hiring managers (AI PM, AI strategy, product)
**What they should conclude:** *This person can own an AI product end to end.*
- Data product thinking (sources, pipeline, schema, freshness).
- AI architecture, not prompt-fiddling (gateway, grounding, evaluation).
- Execution: a live app + tests + CI, not a Figma mockup.
- Judgment: knows what NOT to automate; states limitations honestly.
**Lead lines for them:** "The model is not the source of truth — the system is." / "80% execution accuracy and zero invented numbers, by design."

## 2. Founders (potential build partner / early hire / collaborator)
**What they should conclude:** *This person can turn an idea into a structured, shippable product.*
- MVP instinct: proof-of-work first, roadmap second.
- Understands scaling, workflows, and business models — not just tech.
- Ships. Then hardens. Then points at revenue.
**Lead lines for them:** "An open dashboard is not a product. Here's the path that makes it one." / "I build the system, then I make it defensible."

## 3. Product leaders (peer credibility, network depth)
**What they should conclude:** *This person thinks like a PM who can also build.*
- Problem decomposition into layers (data / logic / AI / UX / eval).
- User-journey clarity and roadmap sequencing.
- Risk & trust awareness baked into design, not bolted on.
**Lead lines for them:** "I designed it as layers, not a prompt." / "Trust has to be measured — so I measured it."

## 4. AI builders / engineers (technical respect, community)
**What they should conclude:** *This person understands grounded LLM systems in production.*
- Text-to-SQL with static validation + execution guard + self-correction.
- Deterministic numeric grounding (every number in prose must exist in the result set).
- Provider-agnostic gateway, prompt caching, token budgets, refusal logic.
- Evaluation: execution accuracy + faithfulness, with real numbers.
**Lead lines for them:** "The LLM writes SQL; the database returns the numbers." / "Faithfulness 0.94, refusals 5/5 — measured, not asserted."

## The through-line that serves all four
Systems thinking + trust engineering + business sense. Recruiters see execution, founders see
shippability, product leaders see judgment, engineers see rigor. Same artifact, four doors in.

## Tone calibration per audience (subtle, not separate posts)
- Recruiters/founders → outcomes and decisions.
- Product leaders → structure and sequencing.
- Engineers → mechanism and metrics.
Rotate emphasis; never write four different people. Write one person — a builder — who happens
to be legible to all four.
