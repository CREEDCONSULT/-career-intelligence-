# Narrative Pillars

Ten pillars. Each has: the belief, the hook, the proof, and the line to land on.
Pull from these all campaign long so posts stay varied but on-message.

---

## 1. Why I built it
**Belief:** I wanted to prove I build *with* AI, not just prompt it.
**Hook:** "I stopped treating AI as something I ask. I started treating it as infrastructure."
**Proof:** A working system: data → analytics → AI → UX → evaluation.
**Land on:** "So I built a Career Intelligence Dashboard."

## 2. The problem with generic career advice
**Belief:** Most career advice sounds smart and is ungrounded.
**Hook:** "Career advice has a data problem. It sounds intelligent. It rarely is."
**Proof:** The dashboard answers from 97,227 real Toronto postings, not vibes.
**Land on:** "Advice should be grounded, not guessed."

## 3. System architecture
**Belief:** Good AI products are designed as layers, not prompts.
**Hook:** "I didn't start with a model. I started with layers."
**Proof:** Data → Analytics → AI (guarded) → UX → Evaluation → Productization.
**Land on:** "The architecture is the product."

## 4. The data layer
**Belief:** The hardest, least glamorous part is where the credibility lives.
**Hook:** "Everyone wants the AI layer. The data layer is where trust is earned."
**Proof:** Job Bank, Statistics Canada, Indeed Hiring Lab, Lightcast, NOC 2021 — normalized into one clean store.
**Land on:** "Every number traces back to an official source."

## 5. The AI layer
**Belief:** The model should explain and guide — never invent.
**Hook:** "The AI in this system has one job it's not allowed to do: make up a number."
**Proof:** It writes SQL; the database returns the figures; it narrates only what's there.
**Land on:** "The model translates. The system decides."

## 6. Guardrails & evaluation
**Belief:** Trust must be engineered and measured.
**Hook:** "AI can sound confident and be wrong. So I made confidence irrelevant."
**Proof:** Static SQL validation → execution → numeric grounding → refusal on unsupported. 80% accuracy, 0 invented numbers, 5/5 refusals.
**Land on:** "This is the difference between a chatbot and an AI product."

## 7. UX & dashboard design
**Belief:** A system nobody can use isn't a product.
**Hook:** "The intelligence is useless if the interface hides it."
**Proof:** 8 modules — Ask the Data, Career Advisor, Skill Demand, Salary Ranges, Role Fit, Resume Studio, Market Context, Market Brief — each showing its sources.
**Land on:** "Every answer shows its work."

## 8. Productization roadmap
**Belief:** A dashboard becomes a product when it has users, workflows, trust, and a business model.
**Hook:** "Right now it's proof-of-work. Here's the line to a product."
**Proof:** Open demo → gated beta → personal intelligence layer → coach/institution dashboards → market expansion → API.
**Land on:** "I designed the ramp before I needed it."

## 9. Business-model possibilities
**Belief:** Strategy that ignores revenue is a hobby.
**Hook:** "The interesting question isn't 'is it cool.' It's 'who pays, and for what.'"
**Proof:** B2C career intelligence, B2B workforce/coach dashboards, a labour-market API/data layer.
**Land on:** "The dashboard is the wedge. The data layer is the moat."

## 10. My personal operating system
**Belief:** AI is how I stay ahead — as a repeatable method, not a trick.
**Hook:** "This dashboard is one artifact of how I operate."
**Proof:** Deconstruct the system → build the workflow → automate the intelligence. Applied to careers here; to research, strategy, and content elsewhere.
**Land on:** "To build the future, first deconstruct the architecture of the present."

- "Career advice should not just sound intelligent. It should be grounded."
- "AI as infrastructure, not AI as a feature."
- "The LLM writes the SQL. The database returns the numbers."
