The problem

Career advice has a data problem

It sounds intelligent. It's rarely grounded. "Learn in-demand skills" — which ones, in which city, growing or fading, paying what? Most advice can't answer, because it runs on vibes, not data.

I wanted career answers that trace back to a source — and an AI that admits when it can't.

The approach

Design it as a system, not a prompt

Data first. AI second. UX third. That order was the strategy. A language model on top of bad data is just a confident way to be wrong — so most of the real work went into the layers underneath the model.

Data → Analytics → AI (guarded) → UX → Evaluation → Productization
The data layer

Five official sources, one clean store

  • Job Bank Canada — postings & wages
  • Statistics Canada — job vacancies
  • Indeed Hiring Lab — hiring momentum, AI-share of postings
  • Lightcast — skills taxonomy
  • NOC 2021 — occupation classification

Different formats, different geographies — normalized into one queryable store of 97,227 Toronto postings and 5,148 skills, refreshed on an automated monthly schedule.

The AI layer

The model explains — it never invents

The AI answers a question by writing a query, not by guessing. The query is validated, executed read-only against the data, and the model narrates only the numbers that came back. Every figure in an answer is checked against the result set; unsupported numbers don't ship.

Question → LLM writes SQL → validate (SELECT-only) → execute → result table → narrate → grounding check → answer | else refuse

The product

Eight modules; every answer shows its work

  • Ask the Data · Career Advisor · Skill Demand · Salary Ranges
  • Role Fit · Resume Studio · Market Context · Market Brief

The Resume Studio parses uploads token-free, matches a résumé to real in-demand roles (8/8 top-5 on test profiles), and reviews/tailors/drafts — without fabricating experience.

Productization

The ramp, designed before it was needed

Open proof-of-work (now) → gated beta → personal intelligence layer → coach/institution dashboards → market expansion → API. The whole engine is market-configurable — one config retargets it to a new city. The dashboard is the wedge; the data layer is the moat.

Reflection

What this proves

AI strategy becomes real when it leaves the slide deck and turns into a working system.

This isn't a scaled product. It's Phase 0. But it demonstrates the whole method I work by — research → systems → AI workflows → product → scale — as a working artifact you can click.
